## Badge list response fields [C]
`BadgeListResponse.DataDTO` (`GET api/app/badge/list`):
- `badgeId` (String)
- `badgeName` (String)
- `connectMode` (String) - mapped into UI `DeviceItem.deviceType`
- `signalName` (String)
- `url` (String) - image URL
- `createTime`, `updateTime` (Long)

`w7/h.java` builds `DeviceItem(badgeName, connectMode, ..., url, ..., badgeId, signalName)`. Home logic (`w7/i`, `w7/p0`) compares `deviceType` to the literals `"BT"` and `"WiFi"`. So the server field name is `connectMode`; the in-app name is `deviceType`. Docs that say `deviceType` on the wire for the list endpoint should say `connectMode` [C].

`POST api/app/badge/select-badge` only sends `badgeId`. It does not return the catalogue.

## Hard-coded model names? [C]
No NIKKO / NANO / NIJI (or other Beambox product SKU) string is hard-coded as the BT vs WiFi decision. Transport is whatever `connectMode` the server returns for that `badgeId`. Open item U in `docs/models.md` stays [U]: which catalogue rows are BT vs WiFi is not in the APK.
