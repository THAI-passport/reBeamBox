## How the app learns a new **Android** version exists [C]
- Endpoint: `POST app/api/apk` with `AppUpdateRequest{currentVersion, type}`.
- Response: `AppUpdateResponse.data` has `needUpdate`, `currentVersion`, `latestVersion`, and `apkInfo{apkId, apkUrl, apkVersion, text, ...}`.
- This is the **phone app** APK updater, not badge firmware. `apkUrl` is an APK download URL.

## How badge firmware OTA is wired [C]
- UI: `AboutActivity` binds `R.id.layout_ota` (OTA entry on the About screen).
- SDK package: `com.jieli.jl_bt_ota` (impl `BluetoothOTAManager`, `RcspOTA`, `OtaDataCache`, `DeviceReConnectManager`, `ReadFileThread`).
- Native: `libjl_ota_auth.so` (and related Jieli libs listed in `docs/binaries.md`) provide OTA auth / `parse_fw_info` / file filter JNI. Presence confirmed under `analysis/work/so2/lib/arm64-v8a/`.
- Input to the SDK: `BluetoothOTAConfigure` supplies either `firmwareFilePath` (on-disk file) or `firmwareFileData` (byte array). `OtaDataCache.init` refuses null configure / missing file / empty bytes.
- Transfer: `BluetoothOTAManager.startOTA(IUpgradeCallback)` over the existing Bluetooth link (RCSP OTA). Reconnect during OTA is handled by `DeviceReConnectManager` using an OTA advertise flag (`JL_Constant.OTA_IDENTIFY`).
- BadgeSdk also exposes a read-only `BadgeDeviceInfo.firmwareVersion` string from the connected badge; that is status, not an update path.

## Size / version checks [C]
- `OtaDataCache` / `ReadFileThread` error if path missing, IO fails, or requested slice is out of range.
- `BluetoothOTAManager.FILE_CACHE_DATA_LIMIT` gates whether small files are fully buffered in memory vs streamed via `RandomAccessFile`.
- `startOTA` no-ops with a warning if the Bluetooth device is disconnected or an OTA is already in progress.
