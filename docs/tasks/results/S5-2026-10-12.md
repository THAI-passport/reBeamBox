## Receive paths found
| Path | Class area | What it parses |
|---|---|---|
| nn20 notify 0x01F2 | nn20 BLE manager receive handler | one framed message: head 0xA0, type, length, UTF-8 JSON, checksum |
| BadgeSdk control 0x9E over RCSP | SDK connection class `onReceiveData` | six command codes (below) |
| Payment certificate notify 0x4A02 | a small GATT callback class | data forwarded to the payment certification component; unrelated to pictures |
| BluFi notify | an Espressif BluFi client class | Wi-Fi provisioning replies (only the pets device screen uses it) [I] |
| Jieli OTA notify | the OTA library | firmware update protocol; never used by the client |
| Wi-Fi control socket | the camera and upload screens | single 2-byte words and text, below |

## Inbound message types
| Path | Message | App behaviour | Source area |
|---|---|---|---|
| nn20 | status JSON, payload over 30 bytes | free space to the storage display, time_mode to the loop-mode switch; other keys ignored | receive handler |
| nn20 | text containing GetPacketSuccess or GetPacketFail | upload acknowledgement | message dispatcher |
| nn20 | frame failing the checksum | dropped, buffer trimmed | receive handler |
| BadgeSdk | 0x61 | bind reply | `onReceiveData` |
| BadgeSdk | 0xC7 | device info (storage etc.) | same |
| BadgeSdk | 0xDB | picture sizes | same |
| BadgeSdk | 0xFF | command ack, one status byte, forwarded to ack listeners | same |
| BadgeSdk | 0x27 | battery: two bytes (status, level) | same |
| BadgeSdk | 0x81 | camera command as an integer: remote shutter, leave camera mode | same |
| BadgeSdk | any other command code | ignored by the app (shared Jieli decoder table) | same |
| Wi-Fi | 0x007A, 0x007B, 0x007F | shutter, camera on, badge left camera mode | camera screen |
| Wi-Fi | 0x006A (contained in the hex) or 0x006B, text `SD:<n>KB` | upload start ok, failed, free storage | three upload screens |

## Negative result
No code path parses touch coordinates or any touch gesture from the badge. Searched: the nn20 BLE manager and its frame and JSON classes, the BadgeSdk package including connection, transfer and API callbacks, the network package, and the Wi-Fi reader words in the camera and upload screens. The only hits for battery are the BadgeSdk battery listener and the single 0x27 handler. Battery is therefore a BadgeSdk-only value; nn20 and Wi-Fi expose none to the app [C]. Whether the badge sends touch or other data that the app ignores is [U] and is the job of HW-13 (capture with the vendor app while touching the screen).
